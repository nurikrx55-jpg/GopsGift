# Памятка по проекту

Коротко о том, что нельзя понять из одного кода. Подробности — в
[README.md](README.md) и [deploy/README.md](deploy/README.md).

## Что это

GapsGift — Telegram Mini App с подарками. Репозиторий называется `GopsGift`, и
ключи в базе остались `gg:*`: переименование стоило бы потерянных данных.

## Где работает

**Свой сервер, не Vercel.** Vercel выключен 8 октября 2026 года.

    nginx (gapsgift.online, TLS) → node server.mjs на 127.0.0.1:3000 → Postgres (Neon)

`server.mjs` раздаёт статику и сам зовёт обработчики из `api/`. Файл
`vercel.json` остался от прежней схемы и ни на что не влияет. Секреты
(`DATABASE_URL`, `BOT_TOKEN`, `WEBHOOK_SECRET`) лежат на сервере в
`/etc/gapsgift.env`, служба называется `gapsgift`.

## Общая копия — GitHub

Проект правят с двух сторон: из сессии на ноутбуке и из облачной сессии с
телефона. Чтобы правки не терялись и не затирали друг друга:

- **начинай работу с `git pull`** — чужие правки могли прийти, пока тебя не было;
- **заканчивай `git push`** — иначе вторая сторона о сделанном не узнает;
- не держи готовую работу незакоммиченной: для другой стороны её не существует.

На ноутбуке правки с GitHub подтягиваются сами, раз в минуту — `deploy/mac-sync.sh`
под launchd (см. deploy/README.md). Но если в папке осталась несохранённая
работа, он пропускает обновление: `git pull` в начале работы всё равно за тобой.

Если `git pull` ругается на расхождение, разбери его по-честному (посмотри оба
изменения и соедини), а не затирай чужое силой.

## Выкладка

С машины, у которой есть ssh-ключ от сервера: `git commit`, затем
`deploy/push.sh`. Скрипт отправляет содержимое коммита, сервер сам ставит
зависимости и перезапускает службу. Прошлый выпуск лежит в `/opt/gapsgift.old`,
откат — переименование папки.

Без ssh-ключа (например, из облачной сессии) выкладка недоступна: отправь
коммит на GitHub и скажи об этом человеку.

## Проверка до выкладки

Локальный стенд живёт в `.claude/dev/` и **в репозиторий не попадает**: он
гоняет настоящий Postgres в памяти (pglite) через тот же SQL и подписывает
initData тестовым токеном. Там же тесты: `node .claude/dev/market-test.mjs`,
`db-test`, `fees-test`, `withdraw-test`, `ton-test`. Если этой папки нет,
запустить приложение целиком не получится — правь код и проверяй чтением.

## Договорённости

- **Сообщения бота — простым текстом, без эмодзи.**
- Правки внешнего вида сперва показывать скриншотом, и только потом выкладывать.
- Стиль «жидкого стекла» уже описан в `style.css`: переменная `--glass-edge` и
  класс `.glass`. Свой вариант не изобретать.
- Приложение открывается только из приложений Telegram (компьютер и телефон),
  браузеру показывается QR-код.
- Вывод TON ручной: человек оставляет заявку, админ отправляет сам и отмечает
  её в разделе «Выводы».
- Передача подарка оплачивается звёздами Telegram, цена — в админке.
- Комментарии в коде на русском, объясняют «почему», а не «что». Держись того
  же тона, что и в соседних строках.

## Доступ в админку

`admin.html`, вход только для id из `ADMIN_IDS` (по умолчанию — владелец).
Подпись Telegram проверяет сервер, подделать доступ из браузера нельзя.
